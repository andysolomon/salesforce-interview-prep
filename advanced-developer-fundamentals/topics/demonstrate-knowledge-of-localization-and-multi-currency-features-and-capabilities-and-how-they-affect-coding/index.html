Page 3 · Learning Objectives

After studying this topic, you should be able to:

  • Explain the role and importance of localization tools in orgs that work with multiple languages, locales, or currencies.
  • Identify best practices when working with a multi-language, multi-locale, or multi-currency Salesforce org.
  • Identify common use cases for localization tools in working with Apex or low-code customizations.
  • Describe how to retrieve local language, locale, and currency programmatically.
Page 4 · Introduction

Introduction

Salesforce provides tools for creating apps that can accommodate multiple languages, currencies, and locales. Object and field label translations can be provided declaratively through the user interface by specified users. To ensure that information displays correctly to all users regardless of language, locale, or preferred currency, developers should use functions and special label notations provided in SOQL, Visualforce, and Apex.

Page 5 · Tools for Localization

Tools for Localization

Multi-Currency Tools

  • CurrencyType object: currencies used by org.
  • DatedConversionRate object: dated exchange rates.
  • CurrencyIsoCode field: defines the currency on a record.
  • convertCurrency(): converts a record's currency to the user's currency value in SOQL/SOSL.
  • FORMAT(): displays a currency value both in the original record source and in the current user's currency in SOQL/SOSL.

Multi-Language Tools

  • Translation Workbench & Rename Tabs & Labels: enter translations for objects and fields.
  • {!$ObjectType.[object].fields.name.label}: displays a translated label in Visualforce.
  • System.Label: accesses translated labels in Apex.
  • toLabel(): translates a label in SOQL/SOSL.

Multi-Locale Tools

  • FORMAT(): formats number/date/time/currency fields based on user's locale in SOQL/SOSL.
  • <apex:outputField>: formats data according to the user's locale.

General Guidelines

Page 7 · Language / locale / currency

Language / locale / currency

Deploying Salesforce applications to international communities requires adapting to variations in language, locale, and currency.

Language

Controls labels and translations.

Locale

Controls formatting of information such as dates, times, and names, as well as the use of period vs. comma for thousands and decimal separators.

Currency

Controls currency display such as the currency symbol and conversion based on defined exchange rates.

Page 8 · Dynamic SOQL/Apex & strings

Dynamic SOQL/Apex & strings

Dynamic SOQL/Apex

Dynamic SOQL and Apex can be used for code that is language-dependent, locale-dependent, or currency-dependent.

Strings and Lengths

Building logic based on literal string values or specific string lengths in Apex code or formulas should be avoided — the logic may break (for example, after a translation changes the current language).

Interview angle

Classic gotcha: a formula that compares to the literal "Closed Won" string breaks the moment the org is translated. Compare to picklist API values or status flags, not display labels.

Multi-language

Page 12 · Language support levels

Language support levels

Salesforce has three levels of language support: fully supported, end-user, and platform-only.

Fully Supported Languages

All Salesforce features and UI texts are automatically translated into the org's default language.

End-User Languages

Labels for all standard objects and pages — except admin pages, Setup, and Help — can be translated. Right-to-left languages are supported but have some limitations.

Platform-Only Languages

Custom apps developed in Salesforce can be localized using platform-only languages — translating custom labels/objects/fields and most standard labels/objects/fields.

Page 13 · Text length & Translation Workbench

Text length & tooling

Text Field Lengths

Text field lengths should be sufficient to accommodate longer translations. A three-word English phrase may be a fifteen-word Russian phrase.

Translation Tools

Use the Translation Workbench and Rename Tabs and Labels screens to:

  • Translate customizations.
  • Change labels in installed custom managed packages.
Page 14 · Adding languages

Add languages in Translation Workbench

The Translation Workbench can add supported languages and manage translations for metadata and data labels in the org. Found at Setup → User Interface → Translation Workbench → Translation Language Settings.

Page 15 · Translate via Workbench

Translate via Translation Workbench

From the Translate page in Translation Workbench:

  1. Select a language (if you're a translator for more than one).
  2. Select a setup component.
  3. If necessary, select an object and aspect (e.g. a workflow task has Object: Account/Contact and Aspect: Subject/Comment).
  4. Double-click in the translation column to enter new values. Tab to next row.
Example: Master Field Label "First Name" → Field Label Translation "Vorname" (German, Custom Field on Student object).
Page 16 · Rename Tabs and Labels

Translate Tabs and Labels

The Rename Tabs and Labels page in Setup can be used to translate tabs and labels. Example fields for French translation of the Volunteers tab:

  • Tab: Volunteers
  • Language: French
  • Record Name: Volunteer Name
  • Gender: Masculine
  • Singular: Bénévole — Plural: Bénévoles
Page 17 · Recommendations for localization-ready apps

Recommendations for localization-ready apps

Visualforce Page

{!$ObjectType.[object].fields.name.label} can be used to display labels.

SOQL / SOSL

The toLabel() function can be used in SOQL or SOSL to translate labels.

Apex

System.Label in Apex can be used to make translation-friendly error messages.

Picklists

Picklists should be used whenever possible instead of allowing users to type in free-form text.

Email Templates

Use Visualforce email templates instead of standard email templates for locale-aware and translation-friendly templates.

Page 18 · Translate Custom Labels

Translate Custom Labels

Translations can be created for custom labels in the Custom Labels page in Setup. Example: a custom label Invalid_Name_Format with English value "The name format you entered is invalid for this record." Then add translations as needed.

Page 19 · Custom label in Apex

Custom label in Apex

if (isValidNameFormat(name)) {
  processName(name);
} else {
  // show multi-language friendly error message
  ApexPages.addMessage(
      new ApexPages.Message(ApexPages.Severity.ERROR, System.Label.Invalid_Name_Format)
  );
}
A custom label is accessed in Apex using System.Label to display a localized error message based on the current user's settings.
Page 20 · Accessing label dynamically

Accessing label dynamically

// If namespace is an empty string, it refers to the org namespace
// If namespace is set to null, it refers to the package namespace
String namespace = ''; // if empty

String label = 'OutOfStock';
String language = 'de'; // language ISO code for German

String message = '';

if (System.Label.translationExists(namespace, label, language)) {
  message = System.Label.get(namespace, label, language);
} else {
  // get default translation if not available
  message = System.Label.get(namespace, label);
}
Label.translationExists checks whether a translation exists for the specified language before trying to fetch it.
Page 21 · Directionality & formatting

Directionality & formatting

Directionality

Languages that are read left-to-right and right-to-left should be considered when designing UIs. It can affect the layout order of fields and CSS styling.

Data Formatting

Locale-aware components such as <apex:outputField> should be used to automatically format data based on the underlying field type — currency, date, checkbox, picklist, etc.

Component Labels

In the Lightning App Builder, the expression {!$Label.customLabelName} can be used to specify localized custom component labels.

Page 23 · Multi-currency overview

Multi-currency overview

Salesforce offers features to support orgs that use multiple currencies. Some features are only available when multi-currency is enabled for the org.

Currency ISO Code

All objects with currency fields also have a CurrencyIsoCode field, which specifies the currency the numeric amount represents.

convertCurrency()

SOQL/SOSL function that converts a currency value into the current user's currency.

FORMAT()

SOQL/SOSL function applying localized formatting of a currency, number, date, or time. Can also display the value in the original record source and in the current user's currency.

Page 27 · FORMAT function

FORMAT function

When using format() on a currency field, the value is formatted according to its associated currency ISO code per record. A converted value based on the user's currency is also displayed.

Page 29 · Visualforce outputField

Handle multiple currencies in Visualforce

<!-- the opportunity amount will automatically format based on the user's settings-->
<apex:outputField value="{! Opportunity.Amount }"/>
outputField cannot be used to display currency values when Advanced Currency Management is enabled in the org. In this case, the outputText component can be used.
Page 30 · @salesforce/i18n in LWC

Localization in Lightning Web Components

LWCs can adapt to user languages, currencies, and timezones via the @salesforce/i18n scoped module.

LocalExample.js

import { LightningElement } from "lwc";
import LOCALE from "@salesforce/i18n/locale";
import CURRENCY from "@salesforce/i18n/currency";

export default class LocalExample extends LightningElement {
  myLocale = LOCALE;
  myCurrency = CURRENCY;
  localDate;
  localPrice;

  connectedCallback() {
      let date = new Date(2024, 1, 14);
      this.localDate = new Intl.DateTimeFormat(LOCALE).format(date);
      let price = 11.99;
      let setting = Intl.NumberFormat(LOCALE,
          { style: 'currency', currency: CURRENCY });
      this.localPrice = setting.format(price);
  }
}

LocalExample.html

<template>
  <div class="slds-color__background_gray-1 slds-box">
      My locale is {myLocale}.<br />
      The local date is {localDate}.<br />
      My currency is {myCurrency}.<br />
      The price is {localPrice}
  </div>
</template>
Sample output for a user in the Philippines using AUD:
My locale is en-PH. The local date is 2/14/2024. My currency is AUD. The price is A$11.99.

Bonus · Quick-Reference Cheatsheet

Quick-Reference Cheatsheet

UserInfo (Apex)

  • UserInfo.getLanguage() → e.g. en_US.
  • UserInfo.getLocale() → e.g. en_US.
  • UserInfo.getDefaultCurrency() → e.g. USD.
  • UserInfo.isMultiCurrencyOrganization() → branch logic on this.

Translations

  • Visualforce labels: {!$ObjectType.[Object].fields.name.label}.
  • SOQL/SOSL: SELECT toLabel(StageName) FROM Opportunity for picklist label translation.
  • Apex error messages: System.Label.MyLabelName.
  • Dynamic per-language fetch: System.Label.get(namespace, label, language); guard with Label.translationExists(...).
  • LWC component labels: import from @salesforce/label/c.MyLabel; Lightning App Builder: {!$Label.customLabelName}.

Multi-currency

  • Every currency field comes with a sibling CurrencyIsoCode.
  • SOQL helpers: convertCurrency(field) + FORMAT(field) — combine for "show me everything in the viewer's currency".
  • CurrencyType = active currencies + base conversion rates; one row has IsCorporate=true.
  • DatedConversionRate = time-bounded rates (used when "Dated Exchange Rates" / Advanced Currency Management is on).
  • Visualforce: <apex:outputField> handles currency formatting unless Advanced Currency Management is on → fall back to <apex:outputText>.

LWC i18n

  • Scoped imports: @salesforce/i18n/locale, @salesforce/i18n/currency, also timeZone, language, etc.
  • Pair with browser built-ins: new Intl.DateTimeFormat(LOCALE), Intl.NumberFormat(LOCALE, { style:'currency', currency:CURRENCY }).

Anti-patterns to memorize

  • Comparing to literal display strings ('Closed Won') — breaks on translation. Use picklist API values or status flags.
  • Hardcoded string-length limits — a 3-word English phrase can be a 15-word Russian phrase.
  • Free-form text input where a picklist + toLabel would translate cleanly.
  • Standard email templates for international audiences — use Visualforce email templates instead.
  • Assuming LTR layouts. RTL languages flip field order and CSS.

Interview-friendly one-liners

  • "Locale ≠ language" — locale controls date/number formatting; language controls labels.
  • "toLabel() in SOQL is the most surgical way to get translated picklist values without leaving your query."
  • "System.Label in Apex automatically picks the right translation based on the running user's language."
