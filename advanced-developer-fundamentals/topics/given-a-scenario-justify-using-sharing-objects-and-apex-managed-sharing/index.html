Page 4 · Introduction

Introduction

Apex managed sharing is one of three sharing capabilities in Salesforce.

  • Managed sharing: access granted by the system based on record ownership, role hierarchy, and sharing rules.
  • User managed sharing (a.k.a. manual sharing): the record owner — or any user with Full Access — shares the record with a user or group of users.
  • Apex managed sharing: use Apex code to build sophisticated and dynamic sharing settings that are not otherwise possible. Use when neither Managed nor User-managed sharing is suitable.
Page 5 · Apex Managed Sharing overview

Apex Managed Sharing — at a glance

Share Objects

A share object exists for a Salesforce object if the org-wide default sharing setting of the object is Private or Public Read Only.

Sharing Reasons

Apex Sharing Reasons can be defined for custom objects; RowCause is used to specify the sharing reason in Apex code.

Recalculation

Apex Managed Sharing is recalculated automatically when the org-wide default sharing setting of a custom object is updated.

Use Cases

Use when sharing logic is too complex, or depends on field values across multiple objects.

Page 6

Share Objects

Page 7 · Sharing setting

Share objects & the OWD setting

Share objects are used to create sharing and track records that are being shared in an org.

A Share object only exists for an object if the Organization-Wide Default is Public Read Only or Private. If the object access policy is Public Read/Write, no other sharing policy is necessary.
Page 8 · Standard / custom shares

Standard vs custom share objects

Standard Shares

Append 'Share' to the object name. The Share object for Account is AccountShare.

Custom Shares

Append '__Share' to the object name. The Share object for MyCustomObject is MyCustomObject__Share.

Custom Objects

Although Share objects exist for both standard and custom objects, Apex sharing reasons and Apex managed sharing recalculation are only available for custom objects.

Page 9 · Sharing types & object existence

Sharing types & object existence

User Managed Sharing

Manually sharing records using Apex is supported by all custom objects, but only by a few standard objects: Account, Contact, Opportunity, Case.

Sharing Object Existence

A Sharing object only exists for an object if the Organization-Wide Default is Public Read Only or Private. If the object access policy is Public Read/Write, no other sharing policy is necessary.

Page 10 · Apex Managed & recalculation reasons

Apex Managed Sharing's custom-object territory

Apex Managed Sharing

Uses Apex sharing reason, which is only supported in custom objects, to build sophisticated and dynamic sharing settings that are otherwise not possible.

Reasons and Recalculation

Apex sharing reasons and Apex managed sharing recalculation are only available for custom objects.

Page 11 · Share object fields

Share object fields (custom object)

When writing Apex code for sharing a record, these Share object fields for a custom object must be defined:

ParentId

The ID of the record being shared.

UserOrGroupId

The ID of the user or public group being granted access.

AccessLevel

Either 'Read' or 'Edit'. Defines the access level.

RowCause

Specifies the reason why the user or public group is being granted access.

AccessLevel can also be 'All' — but All is an internal value and cannot be granted in Apex. Only Read and Edit are valid values to set.

Page 13 · Implicit shares note

Implicit shares note

Salesforce allows for skipping Implicit Share records for Cases, Contacts, and Opportunities associated with Accounts, resulting in faster ownership and sharing rule calculations for account-related data.
Page 14

Apex Managed Sharing

Page 15 · Overview

Apex Managed Sharing overview

Sharing Reason

Apex Managed Sharing is programmatic sharing that allows defining a custom sharing reason for the programmatic share.

Custom Object

Custom sharing reasons can only be defined for shares written to custom objects.

Sharing Setting

Objects with a default sharing setting of Private or Public Read Only have a related __Share object.

Share Objects

A share object includes records supporting managed, user managed, and Apex managed sharing.

Page 16 · User managed sharing via Apex

User managed sharing via Apex

User managed sharing (manual sharing) can also be performed programmatically.

Manual Sharing

Apex can perform manual sharing on custom objects and a few standard objects: Account, Contact, Opportunity, Case.

Owner Changes

The RowCause defined is "Manual", and shares using this type of sharing are automatically deleted when the record owner is changed.

Page 17 · Sharing reason & setup

Setting up an Apex Sharing Reason

Apex Sharing Reason

To use Apex managed sharing, a sharing reason must first be defined for the custom object. Apex code can then add or remove entries of the Share object to grant users access when specific conditions are met.

Object Definition

Apex sharing reasons can be created by navigating to the 'Apex Sharing Reasons' related list of the custom object in the Salesforce Classic interface.

Interview angle

Apex Sharing Reasons can only be created in Salesforce Classic. This is a real-world gotcha — administrators expecting to do it in Lightning have to switch UI.

Page 18 · Label/name & RowCause types

Label/name & RowCause types

Label and Name

Each Apex sharing reason has a label and a name. Label is displayed in the UI while viewing sharing for a record; the name is used when referencing the reason in the API and Apex.

RowCause Type

Either a custom or 'Manual' RowCause can be used in Apex code to create records in share tables. In Apex managed sharing, a sharing reason must be used.

Manual RowCause

A 'Manual' RowCause is used to treat the share record as if it were created by manual sharing. This value is used in declarative or programmatic user managed sharing.

Page 19 · Setup UI

Setup UI for Apex Sharing Reasons

Apex Sharing Reasons and Apex Sharing Recalculation are managed in the detail page of a custom object in the Salesforce Classic interface. Example reason: "Share with Specialist".

Page 20 · Apex code example

Apex code example

public static void manualShareReadWrite(Id recordToShareId, Id shareWithId){

  // Create new sharing object
  MyCustomObject__Share shareObject = new MyCustomObject__Share();

  //ID of the object we want to share
  shareObject.ParentId = recordToShareId;

  //ID of the person we want to share with
  shareObject.UserOrGroupId = shareWithId;

  // Access level - valid values are Read, Edit, or ALL.
  // Note that unlike Read and Edit, ALL is an internal value and cannot be granted.
  shareObject.AccessLevel = 'Edit';

  // Fill in this field with an existing, manually created sharing reason
  // defined in the 'Apex Sharing Reasons' section of the custom object definition
  shareObject.RowCause = Schema.MyCustomObject__Share.RowCause.Share_with_Specialist__c;

  // Activate the defined access to the record
  insert shareObject;
}
An Apex Sharing Reason is used for tracking or determining why a record was shared with a user or group of users.
Page 21 · When to use Apex managed sharing

When to use Apex managed sharing

The following conditions require the use of Apex managed sharing:

Capability

Standard sharing functionality is not sufficient, and all attempts to share declaratively have failed.

Combination

Sharing rules depend on a combination of values across multiple objects.

Complexity

The sharing logic is too complex to be established declaratively.

Support

Sharing access is criteria-based, but the evaluated field is not supported by declarative sharing.

Interview angle

Apex Managed Sharing should always be the last option. Interviewers want to hear: "first try OWD + role hierarchy → then sharing rules → then criteria-based sharing → only then Apex." Reaching for code first signals weak Salesforce intuition.

Page 22

Apex Managed Sharing Recalculation

Page 23 · Recalculation triggers

Recalculation triggers

Apex managed sharing rules are automatically recalculated whenever a custom object's org-wide sharing default access level is updated.

Classes Execution

During automatic recalculation, custom recalculation classes are executed.

Manual Invocation

Sharing rule recalculation can be manually invoked from the custom object's setup area.

Page 24 · Recalc class & object association

Recalculation class & object association

Recalculation Class

To enable manual recalculation, an Apex class that implements the Database.Batchable interface must be written.

Object Association

To associate an Apex managed sharing recalculation class with a custom object, the recalculation class is selected in the Apex Sharing Recalculations section of the object definition.

Page 25 · Most permissive rule

Most permissive rule wins

When multiple entries of a Share object apply to a certain user, the most permissive rule is applied. For example, if a user has been granted Read access through managed or manual sharing, and an Apex managed sharing rule grants Read/Write access, then Read/Write access is applied.
Page 26 · Considerations

Other Apex Managed Sharing considerations

Owner Changes

Apex managed sharing is maintained across record owner changes.

Modify All Data

Only users with the 'Modify All Data' permission can add, edit, or delete Apex managed sharing on a record.

Sharing Reasons

A record can be shared multiple times with a user or group using different Apex sharing reasons.

Interview angle

Compare/contrast: Manual RowCause shares disappear when the record owner changes; Apex managed sharing persists. This is a primary reason to choose Apex managed over "manual via Apex".

Scenarios and Solutions

Page 28 · Job → hiring manager

Job record → hiring manager

Scenario

Once a Job record is created by a Recruiter, it needs to be shared automatically with a hiring manager based on the value in a lookup field on the Job record.

Solution

An 'after insert' trigger or a record-triggered flow can be created to share a newly created Job record with its associated hiring manager automatically. A Share record for the Job record needs to be created with ParentId, UserOrGroupId, AccessLevel, and RowCause. The RowCause can be specified by navigating to the 'Apex Sharing Reasons' related list of the Job custom object.

Page 29 · Expense custom object

Expense — sharing by custom field

Scenario

Records of a custom object called Expense in an org need to be shared to users based on values of certain custom fields on the Contact records which they own.

Solution

Apex Managed Sharing allows using Apex to share custom object records programmatically. If the sharing logic is too complex and/or involves other objects, Apex code can be defined to create and insert share records for the custom object records. In this scenario, the share object for Expense would be Expense__Share.

Page 30 · Warehouse — Apex Sharing Reasons

Warehouse — reasons visible to users

Scenario

An organization needs to grant access to users to the Warehouse custom object based on different criteria. The reason for granting access needs to be visible in the user interface.

Solution

Apex Sharing Reasons can be defined for a custom object from the 'Apex Sharing Reasons' related list. It can be used while creating Apex code to provide access to custom object records programmatically. A reason can be specified while assigning the value of the RowCause of the share record. The reason can be accessed using:

Schema.CustomObjectName__Share.RowCause.SharingReason__c
Page 31 · Lead → Opportunity

Lead → Opportunity (standard object)

Scenario

When a lead is converted into an opportunity, the opportunity needs to be shared with the lead owner, if the record meets certain criteria based on computed values from certain fields.

Solution

The Opportunity records created from leads can be shared programmatically with the lead owner using Apex code. However, the RowCause would need to be 'Manual', since custom sharing reasons are only supported by custom objects. This scenario illustrates a programmatic implementation of manual sharing for a record.

Interview angle

Trap question: "Use Apex Managed Sharing on Opportunity." Answer: you can't — Opportunity is standard. You can do programmatic manual sharing with RowCause='Manual', but it's not "Apex Managed Sharing" in the strict sense.

Page 32 · Promotion__c — scenario

Promotion__c — scenario

Scenario

The organization-wide default sharing setting of a custom object named Promotion__c has been set to 'Private'. A developer has created an Apex trigger that shares a record of the custom object programmatically with a marketing manager if the record meets a certain set of criteria.

Page 33 · Promotion__c — solution

Promotion__c — solution

Solution

When the org-wide default sharing setting of a custom object such as Promotion__c is set to Private, a 'share object' exists for the object.

In this scenario, the org will have a share object named Promotion__Share, which can be utilized to share a record of the corresponding custom object using Apex Managed Sharing.

Sharing a record of the object with the marketing manager using an Apex trigger will result in the existence of a share record in the Promotion__Share table. The RowCause of the share record will be defined with an Apex sharing reason when creating the share record.

Bonus · Quick-Reference Cheatsheet

Quick-Reference Cheatsheet

The four fields of a share record

  • ParentId — record being shared.
  • UserOrGroupId — grantee (user or public group).
  • AccessLevel — 'Read' or 'Edit'. 'All' exists but is internal-only.
  • RowCause — 'Owner' | 'Manual' | a custom Apex Sharing Reason (custom objects only).

When a Share object exists

Only when the object's OWD = Private or Public Read-Only. Public Read/Write = no share object, no sharing API.

Naming

  • Standard: Account → AccountShare, Opportunity → OpportunityShare.
  • Custom: MyObj__c → MyObj__Share.

The three "sharing via Apex" flavors

FlavorRowCauseSupported onOwner-change behaviorRecalc on OWD change
Programmatic managedsystem-setn/a (system)maintainedauto
Manual via Apex'Manual'All custom + Account/Contact/Opportunity/Casedeletedn/a
Apex Managed SharingCustom reason (Foo__c)Custom objects onlymaintainedauto + custom recalc class

The decision flow

  1. OWD + role hierarchy enough? → done.
  2. Add owner-based or criteria-based sharing rules.
  3. Need user-initiated sharing? → manual sharing in UI.
  4. Still not enough (complex logic, multi-object criteria, unsupported fields)? → Apex Managed Sharing.

When picking RowCause

  • Custom object + you want the share to survive owner changes → custom Apex Sharing Reason.
  • Standard object (Account/Contact/Opp/Case) → forced to 'Manual' (and shares die on owner change).
  • Want the share to disappear when the record changes hands → 'Manual'.

Gotchas to memorize

  • Most permissive wins across multiple share rows.
  • Apex Sharing Reasons can only be defined in Salesforce Classic — not Lightning Setup.
  • Only users with Modify All Data can add/edit/delete Apex Managed Sharing rows on a record.
  • Recalculation = an Apex class implementing Database.Batchable, attached via the object's Apex Sharing Recalculations section.
  • Implicit shares for Cases/Contacts/Opportunities under Accounts can be skipped for performance.

Reading shares with SOQL

SELECT ParentId, UserOrGroupId, AccessLevel, RowCause
FROM MyObj__Share
WHERE ParentId = :recordId
