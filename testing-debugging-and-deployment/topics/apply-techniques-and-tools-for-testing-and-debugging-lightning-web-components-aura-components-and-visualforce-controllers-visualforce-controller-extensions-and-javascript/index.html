Page 5 · Introduction

Introduction

Since Visualforce controllers and controller extensions are Apex classes, their tests should have code coverage that meets requirements. When testing controllers and extensions, the unit test involves writing code that simulates user input from the Visualforce page.

The Jest testing framework is recommended for testing Lightning web components. For Aura components, several tools are available in addition to Jest such as UTAM, Jasmine, Mocha, Selenium, and WebdriverIO.

This topic also covers JavaScript characteristics — case sensitivity, type coercion, scope, mutability — to help when writing or debugging JavaScript code.

Testing Visualforce Controllers and Extensions

Page 9 · Testing Visualforce Controllers and Controller Extensions

Unit-test characteristics

Like all Apex code, custom controllers and controller extensions should be covered by unit tests.

Class Methods

Unit tests are class methods written to test the business logic and verify code functions as expected.

No Arguments

Annotation

Unit test methods are annotated with @isTest.

Page 10 · Setting up a Visualforce test

Setting up a Visualforce test

High-level code steps for setting up a test of a Visualforce controller or extension:

Apex Class

Create a test class with a test method using the @isTest annotation.

Page Reference

Create a PageReference to the Visualforce page.

Current Page

Pass the PageReference instance to Test.setCurrentPage() to set the current PageReference.

Controller

Instantiate the controller for the Visualforce page.

Extension

If needed, instantiate an extension by passing the controller variable as a parameter to the extension constructor.

Parameters

If needed, pass URL parameters to the controller using:
ApexPages.currentPage().getParameters().put('paramName', 'paramValue');

Page 11 · Assertions & edge cases

Assertions & edge cases

Simulate Input

If needed, use the controller's setter methods to simulate user input for data fields.

Simulate Click

Call the controller's action methods to simulate a user clicking a button.

Assert Results

Assertion methods are used to validate or invalidate business logic output.

Class name gotcha: A test class cannot be named Test. Doing this generates: "Method does not exist or incorrect signature: Test.setCurrentPage(System.PageReference)"
Page redirect: If the controller redirects to another page based on user input, the resulting page name can be checked by calling the getUrl() method of the resulting PageReference variable.

Interview angle

Salesforce loves "what happens if you name your test class Test?" — the answer is that Test.setCurrentPage resolves to your local class, not System.Test, breaking your test.

Page 25 · Writing a Jest Test — full example

Full Jest test example

An LWC component named lwcTestDemo + a Jest test verifying the expected heading, name, and email.

LWC markup (lwcTestDemo.html)

<template>
    <h1>Customer Details</h1>
    <p class="name">Name: Ashley James</p>
    <p class="email">Email: ashley@united.com</p>
</template>

Jest test (lwcTestDemo.test.js)

import { createElement } from 'lwc';
import LwcTestDemo from 'c/lwcTestDemo';

describe('c-lwc-test-demo', () => {

    afterEach(() => {
        // The DOM should be reset after each test.
        while (document.body.firstChild) {
            document.body.removeChild(document.body.firstChild);
        }
    });

    // The 'it' or 'test' keyword can be used to create a unit test block.
    it('displays heading, name, and email', () => {
        const element = createElement('c-lwc-test-demo', { is: LwcTestDemo });
        document.body.appendChild(element);

        const heading = element.shadowRoot.querySelector('h1').textContent;
        const name    = element.shadowRoot.querySelector('.name').textContent;
        const email   = element.shadowRoot.querySelector('.email').textContent;

        expect(heading).toBe('Customer Details'); // 'expect' and 'toBe' for assertions
        expect(name).toBe('Name: Ashley James');
        expect(email).toBe('Email: ashley@united.com');
    });
});

Testing With UTAM

Page 33 · UI Test Automation Model (UTAM)

What is UTAM

UTAM is an open-source tool built by Salesforce that tests any web page and is ideally suited for writing JavaScript or Java UI tests for Lightning web components.

Page DOM elements are represented and referenced as JSON Page Objects. UTAM compiles each JSON Page Object into JavaScript (or TypeScript or Java), which contains properties and methods used in writing tests.

UTAM does not include a test runner but integrates with any testing automation framework. Currently it supports WebdriverIO for JavaScript tests and Selenium for Java.
Page 34 · UTAM example

UTAM example

Page Object JSON declares CSS selectors and element names; UTAM compiles it into a JavaScript module exposing typed accessor methods.

// Sample JSON Page Object created based on HTML below
{
  "root": true,
  "selector": {
      "css": "body"
  },
  "elements": [
      {
          "selector": {
              "css": ".color"
          },
          "name": "color",
          "public": true
      }
  ]
}

<!-- Rendered HTML being tested -->
<body>
   <div class="main">
       <h3>Your favorite color is
           <span class="color">blue</span>
       </h3>
   </div>
</body>
// Sample compiled Page Object (JavaScript)
async getColor() {
   const driver = this.driver;
   const root = await this.getRootElement();
   const BaseUtamElement = _createUtamMixinCtor();
   let element = await _utam_get_color(driver, root);
   element = new BaseUtamElement(driver, element);
   return element;
}

// Sample JavaScript test
const colorCheckRoot = await utam.load(ColorCheckRoot);
assert.ok(colorCheckRoot instanceof ColorCheckRoot);

const color = await colorCheckRoot.getColor();
assert.ok(color); // verify if the element exists on the page

const colorName = await color.getText();
assert.strictEqual(colorName, 'blue');

Case Sensitivity in JavaScript

Page 37 · Case Sensitivity — scenario

Scenario

Unlike Apex or SOQL, JavaScript is case-sensitive.

An Apex developer who recently started learning JavaScript has written a sample JavaScript function that accepts a parameter and logs a string in the browser console based on the passed value. However, when the function was called, an error was encountered.

Page 38 · Case Sensitivity — example

The function

function areYouAwesome(status) {

   if (Status == true) {
       console.log('Stay awesome.');
   } else {
       console.log('You are still awesome.');
   }
}
areYouAwesome(true);
Console error: Uncaught ReferenceError: Status is not defined
Page 39 · Case Sensitivity — solution

Solution

Unlike Apex or SOQL, JavaScript is case-sensitive. The variable name in the if statement should be status, not Status, to match the case in the function parameter definition.

Therefore, change to: if (status == true). Alternatively the parameter in the function definition can be updated instead to match the case.

Page 40

Implicit Coercion in JavaScript

Page 41 · Implicit Type Coercion — scenario

Scenario

JavaScript converts invalid types to valid types. The === and !== operators should be used to compare both the value and data type.

A developer is performing a series of operations and comparisons to determine how JavaScript variables behave based on the operator and operands. However, the results do not seem to make sense.

Page 42 · Implicit Type Coercion — example

Example

let variable1 = 10 * "30";
console.log(variable1);          // 300
console.log(typeof variable1);   // number

let variable2 = 10 + "30";
console.log(variable2);          // "1030"
console.log(typeof variable2);   // string

console.log(false == "");   // returns true
console.log(false == "0");  // returns true
console.log("" == "0");     // returns false
console.log([0] == 0);    // returns true
Page 43 · Implicit Type Coercion — solution

Solution

This behavior is called implicit type coercion. In a single expression with operands of different data types, JavaScript automatically converts an "invalid" data type to a "valid" type. It is best not to use implicit type coercion, to avoid confusion.

To determine whether two variables are equal, use the strict comparison operator (===). It returns true only if both the value and the data type are the same. !== returns true if either value or type differ.

Interview angle

Memorize a few classic gotchas: [] == ![] is true, null == undefined is true but null === undefined is false, NaN !== NaN. Always use === in production code.

Page 44

Truthy and Falsy in JavaScript

Page 45 · Truthy and Falsy

Truthy and Falsy

A truthy is any value that evaluates to true in a Boolean context. A falsy evaluates to a Boolean false value.

Truthy

Any other value (except false) is coerced as true.

Falsy values

  • 0, -0, or 0n (BigInt)
  • "" or '' (empty string)
  • null
  • undefined
  • NaN (not a number)
Page 46 · Truthy/Falsy in conditionals

Truthy/Falsy in conditionals

Conditional statements do not require actual Boolean values and operate based on truthiness/falsiness of any data type.

var a = null; // falsy value
if (a) {
   console.log('branch 1');
} else {
   console.log('branch 2');
}

var b = [0]; // truthy value
if (b) {
   console.log('branch 3');
} else {
   console.log('branch 4');
}
// output: branch 2, branch 3
Watch out: the Boolean function determines a value's truthiness. Surprisingly, Boolean('false') is truthy — non-empty strings are always truthy regardless of content.

Mutable Assignment in JavaScript

Page 48 · Mutable Assignment

var / let / const

KeywordMutableScopeDescription
var Yes function Variable is mutable — can be reassigned as many times as needed. Lives within the function scope.
let Yes block Variable is mutable — can be reassigned as many times as needed. Lives within the block scope.
const No block Variable is not mutable — can be assigned a value only once. Reassigning throws an error. Lives within the block scope.
Page 49 · Mutable Assignment — scenario

Scenario

The code snippet on the next slide contains multiple variable assignments. When the code is executed, the last line (type variable reassignment) throws an "Assignment to constant variable" error. The developer needs to determine why this happens for the type variable but not for the others.

Page 50 · Mutable Assignment — example

Example

// primitive value assignments
var color = "silver";
let topSpeed = 300;
const type = "sedan";

// reassignment
color = "black";
topSpeed = 320;
type = "hatchback"; // oops!
// Uncaught TypeError: Assignment to constant variable.
The type variable is a constant which is assigned a value during its declaration. Reassigning a value to it is not allowed.
Page 51 · const objects

const objects

JavaScript objects are mutable. An object declared with const has the following characteristics:

Mutable

Properties of a JavaScript constant object are mutable.

Extendible

Properties or methods can still be added after declaration or initialization.

Reassign

However, reassignment of the constant variable throws an error.

Page 52 · const object example

const object example

const x = {};

// add a new property
x.skill = 'talking';

// add a new function
x.talk = function(){
   console.log('hello');
};
x.talk(); // prints "hello"

// but...
x = {};      // error!
x = true;    // error!
// Uncaught SyntaxError: Identifier 'x' has already been declared
Page 53

Variable Scope in JavaScript

Page 54 · Function Scope vs Block Scope — scenario

Scenario

The keyword (var, let, or const) used to declare a variable impacts the variable scope.

When the next code snippet is executed, the developer expects to see "I am 16 years old!". However, after running the code, the output was not what was expected.

Page 55 · Function Scope vs Block Scope — var example

The var trap

let howOldAmI = function() {
   var num = 16;

   for (var num = 0; num < 3; num++){
       // do something cool
   }

   console.log('I am ' + num + ' years old!');
};

howOldAmI();
// I am 3 years old!
Page 56 · Function Scope vs Block Scope — solution

Solution

The code prints "I am 3 years old!" because of the declaration of num using var in the for loop. When declared with var, its scope is hoisted to the function scope where the former num is declared. Hence the former num is overwritten in each loop iteration. Improper use of var causes confusion and accidental overwrites.

Page 57 · Function Scope vs Block Scope — let example

Using let instead

let howOldAmI = function() {
   var num = 16;

   for (let num = 0; num < 3; num++){
       // do something cool
   }

   console.log('I am ' + num + ' years old!');
};

howOldAmI();
// I am 16 years old!
const variables also operate within the block scope.

Interview angle

"Why use let over var?" — Block scoping prevents accidental hoisting and reassignment across blocks. Even if you never reassign, the predictability is worth it.

Page 58

Object Notation in JavaScript

Page 59 · Object Notation — scenario

Scenario

Objects can be created using an object literal or an object constructor notation.

A developer has written JavaScript code to create an object called Vehicle and would like to determine any limitations of the object when declaring the variable in this manner.

Page 60 · Object literal

Object literal example

let Vehicle = {
   topSpeed: 300,
   state: '',
   move: function(status) {
       if (status === true) {
           this.state = 'moving';
       } else {
           this.state = 'stopped';
       }
   }
}

Vehicle.move(true);
console.log(Vehicle.state); // prints "moving"
Page 61 · Object Notation — solution

Solution

JavaScript provides two methods to create an object:

  • Object Literal Notation
  • Object Constructor Notation

The Vehicle object above is declared using Object Literal Notation. The limitation is that there can only be one instance of the object. Object Literal Notation is not a recommended practice in modern JavaScript — object literals may be used for encapsulating data, but defining functions within it should be avoided.

Page 62 · Object Constructor

Object Constructor Notation

function Vehicle(topSpeed, state) {
  this.topSpeed = topSpeed;
  this.state = state;
}

Vehicle.prototype.move = function (status) {
  if (status === true) {
      this.state = "moving";
  } else this.state = "stopped";
};

myCar = new Vehicle(300);
myCar.move(true);
console.log(myCar.state); // prints "moving"

yourCar = new Vehicle(250);
yourCar.move(false);
console.log(yourCar.state); // prints "stopped"

Interview angle

Modern JS prefers ES6 class syntax (sugar over prototypes) for multi-instance objects. Be ready to write the same Vehicle as class Vehicle { constructor… move… }.

Page 63

Try…Catch Statement in JavaScript

Page 64 · try / catch / finally

try / catch / finally

JavaScript supports the try…catch statement to catch and handle errors gracefully.

Try

If an error occurs in the try block, code execution ceases and the catch block is executed.

Catch

Receives an object with information about the error. Only available in the scope of the catch block.

Finally

Executed after the try block regardless of whether an exception was thrown.

Page 65 · Syntax forms

Valid syntax forms

A try statement must have at least one catch-block or finally-block.

try {
   // try block logic
} catch (exception_object) {
   // catch block logic
} finally {
   // finally block logic
}

try {
   // try block logic
} catch (exception_object) {
   // catch block logic
}

try {
   // try block logic
} finally {
   // finally block logic
}
Page 66 · try/catch example

Example

Code that may cause errors should be placed inside a try block. When an error occurs, the catch block executes instead of terminating the transaction.

// in this example, a function is used to update a record.
// Should an error occur, the catch block executes and prints any details of the error
function updateAmount(data) {

  try {
      lockRecord(data.id); // lock record
      writeRecord(data);   // update record
  } catch (error) {
      console.log('Error occurred when writing to record: ' + error);
  } finally {
      unlockRecord();      // unlock record whether an error was thrown or not
  }
}

Quick-Reference Cheatsheet

Visualforce controller testing

  • PageReference p = Page.SomePage; then Test.setCurrentPage(p);
  • ApexPages.currentPage().getParameters().put('id', a.Id); for URL params.
  • Standard controller + extension: new ApexPages.StandardController(record), pass into the extension constructor.
  • Use setter methods to simulate input, action methods to simulate clicks.
  • Never name your test class Test — collides with System.Test.

LWC + Jest essentials

  • import { createElement } from 'lwc'; import Cmp from 'c/cmp';
  • describe = suite, it/test = single test, expect(...).toBe(...) = assertion.
  • Always reset the DOM in afterEach() — jsdom is shared across tests.
  • Access shadow DOM via element.shadowRoot.querySelector(...).
  • Async UI: return a Promise from your test.
  • CLI: sf force lightning lwc test setup | create | run, plus npm run test:unit and npm run test:unit:watch.

Aura / cross-component tooling

  • Aura testing options: Jest, UTAM, Jasmine, Mocha, Selenium, WebdriverIO.
  • UTAM = JSON page objects compiled to JS/TS/Java; bring your own runner (WebdriverIO for JS, Selenium for Java).
  • Live debugging: select component in Elements panel → type $0 in Console to inspect — works for @wired data too.

JavaScript foot-guns (in priority order)

  1. Case sensitivity — status ≠ Status. ReferenceError if you mix.
  2. Implicit coercion — always use === / !==. Memorize: 10 + "30" === "1030" (string), 10 * "30" === 300 (number), [0] == 0 === true.
  3. Falsy set — exactly six: 0, -0, 0n, "", null, undefined, NaN. Everything else (including 'false', [], {}) is truthy.
  4. var hoists to function scope — re-declaring var num inside a for overwrites the outer num. Use let.
  5. const objects are still mutable — you can add/change properties; you just can't reassign the binding.
  6. Object literal vs constructor — literal = singleton; constructor (or ES6 class) for multiple instances.
  7. try/catch/finally — must have at least one of catch or finally; finally runs no matter what.
