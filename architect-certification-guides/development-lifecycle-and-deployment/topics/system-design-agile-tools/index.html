Page 4 · Introduction

Introduction

In Salesforce development, leveraging agile tools like Salesforce DX and agile project management tools significantly enhances team productivity and project management. Salesforce DX streamlines the development lifecycle with features like Salesforce CLI, scratch orgs, and Dev Hub, supporting rapid iteration and quality assurance.

Agile project management tools, such as Agile Accelerator, facilitate task management, sprint planning, and real-time collaboration, allowing teams to adapt quickly and efficiently to changes. These tools are foundational in applying agile methodologies, ensuring teams can deliver superior Salesforce solutions swiftly and effectively.

Fed angle

At a central bank, the pairing of Salesforce DX (source-driven development with full version history) and an agile project management tool (sprint tracking, burndown charts) directly supports the audit trail regulators expect: every change traceable to a user story, every deployment tied to a reviewed commit. This is not optional process overhead — it is evidence of controlled change management.

Page 7 · Two Types of Agile Tools

Agile Development Tools

In Salesforce development, two types of agile tools can be utilized to enhance team productivity, collaboration, and project management.

Salesforce DX

Salesforce DX (Developer Experience) is a set of tools used to streamline the entire development lifecycle, improving collaboration, efficiency, and quality.

Project Management Tools

Agile project management tools enable teams to collaborate more effectively, manage tasks efficiently, and deliver value faster and with better quality.

Interview angle

When asked what tools support agile Salesforce development, give the two-category answer: Salesforce DX (developer toolchain — CLI, scratch orgs, Dev Hub, source-driven development) and agile project management tools (Jira, Agile Accelerator, Asana — backlog, sprints, boards). Architects are expected to distinguish the two and articulate why each is necessary; conflating them is a junior-level answer.

Page 8 · Salesforce DX for Agile Development

Salesforce DX for Agile Development

Salesforce DX is designed to support an agile development process. Its features enable faster delivery, higher quality, and more efficient collaboration.

Salesforce CLI

Salesforce CLI allows developers to create and manage Salesforce environments, synchronize source code, execute tests, and deploy applications.

Source-Driven Development

Changes can be managed and tracked in a version control system (VCS) before deploying to Salesforce environments, which enhances collaboration and version control practices.

Scratch Orgs

Scratch orgs are temporary, configurable, and disposable Salesforce environments that support features like isolated development, automated testing, and continuous integration.

Dev Hub

Dev Hub is the main Salesforce org that supports the collaborative and agile aspects of development by enabling the management of scratch orgs.

Fed angle

Source-driven development (VCS integration) is the linchpin for a regulated org: every metadata change lives in Git, reviewable via pull request, tied to a JIRA or Agile Accelerator ticket. The Fed's GitLab CI/CD pipeline relies on exactly this pattern — scratch orgs for isolated feature builds, automated test runs on commit, and Salesforce CLI for scripted deployment to successive environments (SIT → UAT → Prod) with full audit logs.

Page 9 · Advantages of Salesforce DX

Advantages of Salesforce DX

Salesforce DX aligns well with agile development methodologies by providing tools that support rapid iteration, collaboration, and quality assurance.

Enhanced Developer Productivity

Salesforce DX offers enhanced developer productivity through scratch orgs and Salesforce CLI. Developers can quickly spin up scratch orgs, speeding up development and testing cycles.

Better Change Tracking & Collaboration

Source-driven development facilitates better tracking of changes and collaboration among team members, leading to fewer conflicts and more efficient development processes.

Rapid Testing of New Features

Scratch orgs allow for rapid testing of new features in a controlled environment, supporting agile practices like continuous integration and delivery.

Adaptability & Scalability

The configurability offered by Dev Hub and the ability to create and dispose of scratch orgs allows teams to adapt quickly to changing requirements and scale their development efforts.

Scratch orgs are temporary by design — they expire (default 7 days, max 30). This is an exam gotcha: scratch orgs cannot be used as long-lived environments for UAT or production validation. Use Developer Sandboxes or Partial/Full Copy sandboxes for those stages.
Page 10 · Agile Project Management Tools — Features (Part 1)

Agile Project Management Tools — Features (Part 1)

Agile project management tools, such as Jira, Agile Accelerator, and Asana, offer features that support the iterative and incremental nature of agile development.

Backlog Management

Agile project management tools enable prioritization and organization of user stories, tasks, and bugs in a product backlog. Teams can add, assign, prioritize, and manage work items.

Sprint Planning

They support the planning of work for each sprint, allowing teams to assign tasks and user stories to specific sprint cycles. This helps in setting realistic goals based on team capacity and sprint duration.

Board Views

Teams can use Kanban/Scrum boards to track progress, identify bottlenecks, and manage workflow efficiently. These boards provide a visual representation of work items in various stages of development.

Page 11 · Agile Project Management Tools — Features (Part 2)

Agile Project Management Tools — Features (Part 2)

Agile project management tools, such as Jira, Agile Accelerator, and Asana, offer features that support the iterative and incremental nature of agile development.

Collaborative Tools

Features like chat, forums, comments, and document sharing to facilitate real-time communication and collaboration. They ensure alignment and easy sharing of knowledge and feedback.

Reporting & Analytics

Teams can gain insights into project progress, team performance, and delivery forecasts. They can access burndown charts to view the amount of work completed and the total work remaining.

Integration

These tools can be integrated with version control systems like Git, continuous integration tools, and other tools to streamline workflows and automate parts of the development process.

Interview angle

If asked to compare Agile Accelerator to Jira, the key architect point is that Agile Accelerator runs natively inside Salesforce (no separate system, no data sync needed) and is free on AppExchange. For orgs where keeping work tracking inside the Salesforce trust boundary matters — as it would in a regulated environment — that is a meaningful differentiator. Jira requires integration to surface test/build status on user stories; Agile Accelerator does this natively.

Page 12 · Benefits of Agile Project Management Tools (Part 1)

Benefits of Agile Project Management Tools — Part 1

Agile project management tools provide various benefits, including transparency, flexibility, and real-time communication across the development lifecycle.

Collaboration

Centralized communication and project information enhances collaboration among distributed teams and stakeholders, ensuring that everyone is on the same page.

Visibility

Agile tools provide improved visibility into every aspect of the development process, including task status, sprint progress, and the overall project status, facilitating better decision-making and transparency with stakeholders.

Productivity

Streamlined workflows, automation of repetitive tasks, and clear prioritization help teams work more efficiently, reducing time wasted on low-priority tasks and manual processes.

Quality

Continuous feedback loops, regular retrospectives, and the ability to quickly adapt to changes lead to higher quality outcomes and reduced risks associated with project delays or misaligned expectations.

Fed angle

Visibility and collaboration are not just efficiency gains in a central bank context — they are control requirements. Regulators expect that all relevant stakeholders (technology, compliance, risk, business) have real-time access to project status. Agile tools that surface sprint progress and burndown charts to non-technical stakeholders fulfill the same role that status reports do in waterfall, but with greater frequency and accuracy.

Page 13 · Benefits of Agile Project Management Tools (Part 2)

Benefits of Agile Project Management Tools — Part 2

Agile project management tools provide various benefits, including transparency, flexibility, and real-time communication across the development lifecycle.

Consolidation

These tools offer a centralized platform for storing all project artifacts, including project documents. This consolidation facilitates easy access and version control, ensuring everyone works with the most current information.

Integration

Integration with testing and continuous integration tools allow developers to see how changes affect user stories. They can view automated test statuses after code commits and the committed code's build status on user stories.

Scalability

Whether working on small projects or managing large-scale Salesforce implementations, agile tools can scale to meet the needs of the team, providing the flexibility to adapt to changing requirements and priorities.

Predictability

Clear cost estimates and timelines offered by agile sprints, which have a known duration and scope, allow clients to make informed decisions regarding feature prioritization and budget allocation.

Predictability (sprint-based forecasting) is an architect-level selling point when convincing executives to adopt agile. Fixed sprint duration + known velocity = reliable release forecasts — the kind of commitment leadership and audit committees can hold the team to.
Page 14 · Agile Accelerator

Agile Accelerator

Agile Accelerator is a free agile project management tool available in the AppExchange marketplace that allows managing backlog, sprints, user stories, defects, and more.

The tool provides a rich set of navigation tabs including: Work Manager, Sprints, Teams, Kanban Board, Product Tags, Epics, Themes, Reports, Dashboards, Projects, Programs, Portfolios, and Accomplishments. Work items are tracked with IDs, rank, subject, status, sprint, and assignee fields.

Key Capabilities

Backlog management, sprint planning, Kanban/Scrum board views, reporting & analytics, team management, and portfolio-level tracking — all natively within Salesforce.

Why It Matters

Because it runs inside Salesforce, work items share the same platform as the org being developed, simplifying integration with CI/CD pipelines and keeping project data within the Salesforce trust boundary.

Interview angle

Agile Accelerator is the exam's preferred answer when the scenario calls for a native Salesforce agile tool. Mention it is free, available on AppExchange, and supports backlog, sprints, defects, and Kanban boards. Its native nature means no integration required to link work items to Salesforce metadata changes — a significant architectural simplification.

Business Scenario — Cosmic Communications

Read the business scenario below and determine the most appropriate solutions for the company's requirements.

Scenario

Cosmic Communications, a leading provider of cloud-based solutions for the telecommunications industry, is on the verge of a major transformation. The company, known for its cutting-edge technologies and customer-centric products, is adopting Scrum to enhance its agile development processes. With teams spread across different continents, Cosmic Communications faces the challenge of synchronizing efforts, managing workloads efficiently, and delivering high-quality software within shorter timeframes demanded by the market. The Salesforce architect of the company needs to highlight the benefits of adopting agile tools for its development processes.

Requirements & Solutions

Page 18 · Requirement 1

Requirement 1

Scenario

As the company adopts Scrum, the need for an agile development support tool becomes paramount. The tool must facilitate:

  • Effective prioritization of the product backlog to align development efforts with strategic business goals.
  • Management of sprint backlogs to ensure that each sprint is planned with achievable goals and clear priorities.
  • Assignment of work, such as user stories or tasks, to individual team members, promoting accountability and transparency in the development process.
Page 19 · Solution 1 (Part 1)

Solution 1 (Part 1)

Solution

The company should select an agile project management tool that features comprehensive product and sprint backlog management capabilities, alongside robust work assignment functionalities. This tool would enable the teams to:

  • Visually organize and prioritize the product backlog, ensuring that the most critical features are developed first.
  • Plan sprints with a clear overview of the sprint backlog, allowing for better estimation and allocation of tasks.
  • Assign user stories and tasks to developers directly within the tool, enhancing visibility and accountability across the development lifecycle.

Fed angle

At the Federal Reserve, work assignment with accountability is not just a productivity practice — it is an access and responsibility control. Being able to demonstrate that every work item was assigned to a named individual, reviewed by a lead, and closed with documented acceptance criteria satisfies internal audit questions about who approved what change and when. An agile tool that enforces this workflow becomes part of the change management evidence package.

Page 20 · Solution 1 (Part 2)

Solution 1 (Part 2)

Solution (continued)

  • Access burndown charts to view the amount of work completed and the total work remaining for better sprint management.
  • Use features such as chat and comments to communicate important information such as assignment of user stories.

Interview angle

Burndown charts are the most visible agile metric in exam scenarios — they measure sprint health at a glance. An architect should be ready to explain that a burndown chart trending flat (no work burned) signals either blocked work, scope creep mid-sprint, or inaccurate estimation. The ability to surface this signal daily is why agile tools matter more than spreadsheets.

Page 21 · Requirement 2

Requirement 2

Scenario

Due to the growing pressure to increase development velocity while maintaining or improving quality, the company needs to:

  • Consolidate project artifacts in a common repository, providing a single source of truth for all project-related information.
  • Integrate the agile issue tracker with application testing and continuous integration (CI) tools.
Page 22 · Solution 2

Solution 2

Solution

Most agile project management tools offer a centralized platform for the consolidation of all the project artifacts, improving access to information and facilitating better decision-making. Integrating the company's agile tool with testing and continuous integration (CI) tools would enable developers to see automated test statuses and the build status of committed code directly on the user stories, streamlining the development and QA processes. This visibility would assist in identifying and resolving issues more quickly and enhance collaboration between the development and QA teams.

Fed angle

CI integration with the agile tool is the technical backbone of the Fed's controlled deployment pipeline: a developer commits code to GitLab, the CI pipeline runs automated Apex tests and static analysis, and the pass/fail status surfaces directly on the user story in the agile tracker. This creates an unbroken chain — business requirement → user story → code commit → test result → deployment — that change management auditors can follow end to end.

High-Yield Exam Gotchas

  • Scratch orgs expire (default 7 days, max 30) — they are not suitable for UAT or long-running test environments. Use partial/full copy sandboxes for those.
  • Dev Hub must be enabled before scratch orgs can be created — Dev Hub is the prerequisite, not an optional add-on.
  • Agile Accelerator is free and native — when the scenario says "Salesforce-native agile tool" or mentions AppExchange, Agile Accelerator is the answer. Jira/Asana require integration.
  • Burndown chart = sprint health metric — a flat burndown signals blocked work, scope creep, or bad estimates; an architect is expected to recognize and respond to this signal.
  • Source-driven development ≠ change sets — DX/VCS-based deployments are the modern answer for version control and team collaboration; change sets are the legacy approach and are explicitly outclassed for multi-developer teams.
  • CI integration with the agile tracker is the answer for "increase velocity while maintaining quality" — it surfaces automated test results and build status on user stories without manual status updates.
  • Predictability via sprints enables budget/feature decisions by clients — agile is not just a dev methodology, it is a stakeholder communication mechanism.

Fed angle — Tying it together

For a Federal Reserve platform engineer, the highest-value elements of this deck are source-driven development (every change in Git, reviewable, auditable) and CI integration with the agile tracker (automated test results tied to user stories, no manual evidence needed). Together these form the technical spine of a compliant release pipeline: business requirement → backlog item → code commit → automated tests → build status on user story → deployment to successive environments → release approval. Agile Accelerator or Jira provides the workflow layer; Salesforce DX provides the toolchain layer. An architect at the Fed must be able to describe how these layers connect and why each control point matters to examiners.
